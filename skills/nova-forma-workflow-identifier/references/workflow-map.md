# The map of workflows

Use this map to steer where the skill looks. It splits a company's work into four families, each into four areas, so every choice fits one question card and no two options overlap. Each area lists workflows most companies run, written as what starts them and what someone gets at the end.

Use the preloaded workflows when the user's own evidence is thin. Mark any candidate that comes only from this map as "from the standard map", so the user knows it is a starting point and not a finding.

## How the four families split

The test is who receives the result:

- **Commercial**: a customer or prospect, before and around the sale.
- **Operational**: a customer, through the product or service they bought.
- **Support functions**: the company itself: its money, people, contracts and systems.
- **Management**: the leaders who steer the company.

Tie-breaks, so every workflow has one home:

- A customer question or complaint is commercial. The physical work it may trigger, such as a return or a repair visit, is operational.
- A sales contract is commercial. Every other contract, such as with a supplier, partner or employee, is legal.
- Commercial ends when the customer is set up in our systems. Delivering the project or product after that is operational, and billing is finance.
- Planning the work of the coming weeks is operational. Setting direction and money for the year is management.

Anything that fits nowhere goes in as the user's own answer.

## Commercial: win and keep customers

Card description: "Leads, quotes, proposals, orders and keeping customers. Example: inquiry to quote."

| Area | Card description | Workflows, start → end |
| --- | --- | --- |
| Find and qualify leads | Turning interest into first meetings | Inbound enquiry → first meeting · Campaign response → qualified lead · Event contact → follow-up sent |
| Quote and propose | Answering requests with a price | Inquiry → quote the customer can act on · RFP or brief → proposal the client can sign · Price request → approved price |
| Close and onboard | From yes to a customer set up | Order → order confirmation · Sales contract → signed by the customer · Signed deal → customer set up in our systems |
| Serve and grow accounts | Keeping customers and selling more | Customer question → answer · Complaint → closed complaint · Renewal date → signed renewal · Client meeting → follow-up sent |

## Operational: make and deliver what was sold

Card description: "Planning, buying, making or delivering, shipping and service. Example: purchase request to purchase order."

| Area | Card description | Workflows, start → end |
| --- | --- | --- |
| Plan the work | Deciding what to make or staff in the coming weeks | Demand forecast → production or staffing plan · Order book → schedule |
| Buy | Getting what the work needs from suppliers | Purchase request → purchase order · New supplier → approved supplier · Supplier query → answer |
| Make or deliver | Producing the product or running the project | Work order → finished goods · Signed project → kickoff · Workshop booked → materials ready · Quality issue → fix in place |
| Ship and service | Getting it to the customer and keeping it running | Order → shipment · Return request → credit or replacement · Spare-part request → dispatch · Service call → visit closed |

## Support functions: run the company

Card description: "Finance, people, legal and IT. Example: supplier invoice to payment."

| Area | Card description | Workflows, start → end |
| --- | --- | --- |
| Finance | Paying, getting paid and closing the books | Supplier invoice → payment · Customer invoice → cash received · Month end → closed books · Expense claim → reimbursement |
| People | Hiring, onboarding and people moving on | Vacancy → hire · New joiner → productive · Leaver → offboarded · Review cycle → completed reviews |
| Legal and compliance | Other contracts, rules and audits | Supplier or partner contract → reviewed contract · Rule change → updated procedure · Audit request → evidence delivered |
| IT and data | Access, support and data for everyone else | Access request → access granted · IT ticket → resolved · Data request → delivered report |

## Management: steer the business

Card description: "Planning, reporting and decisions at the top. Example: month end to management report."

| Area | Card description | Workflows, start → end |
| --- | --- | --- |
| Plan and budget | Setting direction and money for the year | Strategy cycle → approved plan · Budget request → approved budget |
| Report | Telling leaders how the business runs | Month end → management report · Board date → board pack |
| Decide and approve | Getting decisions made | Investment request → decision · Approval request → signed approval |
| Run change | Choosing and tracking projects | Project idea → approved project · Portfolio review → updated priorities |

## Starting points by kind of business

Offer these as a hint inside a card description when the business type is known. They are hypotheses for the user to correct.

| Kind of business | Workflows that often score high |
| --- | --- |
| Industrial manufacturing | Inquiry to quote, order entry, spare-part requests |
| Professional services and consultancies | RFP to proposal, project setup, client follow-up, timesheet to invoice |
| Distribution and wholesale | Order entry, supplier queries, returns |
| Software and tech | Inbound lead to meeting, customer onboarding, support tickets |
| Any company with many suppliers | Supplier invoice to payment, supplier onboarding |
